Short answer: Cloudflare *can*, but not for free, and not without a paid plan — and it isn't the cheapest of your options.

## Why Workers alone can't do it

Workers have no shell and no long-lived process: no `git`, no `npm`, no `tsc`. Gitea's `act_runner` is a daemon that polls gitea.com for jobs, so it needs a real container.

Workers **Builds** is Cloudflare's own CI, and it connects to **Artifacts, GitHub or GitLab only** — a Gitea repo can't be attached at all ([docs](https://developers.cloudflare.com/workers/ci-cd/builds/)). It is genuinely free though: **3,000 build minutes/month, 2 vCPU, 8 GB RAM, 20 min timeout** on the Free plan.

**Containers** can run `act_runner`, but: Workers **Paid $5/mo required**, still public beta, and a polling runner never idles so it never sleeps. A `lite` instance (1/16 vCPU, 256 MiB, 2 GB disk) running 24/7:

## What was actually wrong

**1. Startup could die on a SQLite lock shared across containers (the crash-loop mechanism).**

`app/store.py` opened the volume database with `sqlite3.connect(path, check_same_thread=False)` — no busy timeout — and then ran `executescript(_SCHEMA)` plus a column migration on *every* connection. The web app scales to several containers that all point at the same `/data/agent.db`; when a few start together, one gets `database is locked`, the lifespan raises, the container exits, Modal restarts it, and the dashboard shows "crash looping". That matches the intermittency: it depends on how many containers start at once, which is why a single request looks fine.

```python
conn = sqlite3.connect(str(path), check_same_thread=False, timeout=30)
conn.execute("PRAGMA busy_timeout=30000;")
conn.execute("PRAGMA journal_mode=WAL;")
```

plus `_load_persisted_state_resilient()` in the lifespan — four attempts with exponential backoff, retrying only on `sqlite3.OperationalError` and still refusing to start on anything else.

**2. The container was looking for the estate on your Windows machine.**

The Modal secrets carry `ECOSYSTEM_ROOT=C:/Users/tap45/ecosystem`, and `modal_agent.py` used `os.environ.setdefault(...)`, so the secret won and the image's staged estate at `/root/ecosystem` was never used. Now `configure_container_env()` assigns the container paths explicitly, and both the app and the probe call that one function instead of keeping their own copy.

The designer is no longer a pure function of the grade, and the decision model now earns its place in the pipeline.

## What changed

`design_next` used to map `grade["weakest"]` to exactly one template, so the same question always produced the same protocol. In [experiment_loop.py](Oncology-Ecosystem-main/Oncology-Ecosystem-main/apps/oncology-agent/app/experiment_loop.py) it now:

- **Ranks a pool of 18 designs** — three per rubric dimension, added alongside the original six templates — with `app/decision.py`'s `score_candidate` (evidence, novelty, feasibility, specificity, risk).
- **Gives the model something real to score.** The first attempt tied every design at 0.5704 because the candidates declared identical structure. Each design now carries a `required_evidence` list and a parseable `estimated_duration`, so scores spread across 0.72–0.88 and the model's gate actually separates them.
- **Lets the model decide eligibility, and the seed decide the pick.** Only designs the model gated as well as its best (same `proceed`/`revise`/`prune` action) are candidates; inside that set a seeded rank-weighted draw chooses. Nothing the model rejected can win on novelty alone.
- **Never re-runs the protocol it just ran.** A design whose exact hypothesis is already in the prior report is dropped while a fresh one exists, so iteration 2 differs from iteration 1 by construction.
- **Rotates the target dimension.** The weakest dimension is the default, not a rule: once an iteration has run, a competing dimension within 0.05 of the weakest can take over, and the previous target is kept only if it still clearly wins.
- **Varies thresholds too**, where more than one is defensible (page size, |d| cutoff, fan-out depth), recorded in the experiment.
- **Records all of it**: `design.seed`, `design.chosen`, `design.candidates` (all 18 with score and action) and each experiment's own decision score. `AGENT_DESIGN_SEED` replays a run exactly.
